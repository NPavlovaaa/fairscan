# 0004. Время событий

Статус: принято · 2026-09-19

## Контекст
Приложение работает без сети, отметка может дойти до сервера через часы после того, как её поставили. При этом нужно знать, когда рекрутер реально отметил человека (для отчёта), и какая из правок новее (для разрешения конфликтов).

## Решение
Клиент ставит markedAt в момент отметки и обновляет editedAt при каждой правке. 
Оба поля — строки ISO 8601 в UTC. 
Сервер при приёме пишет своё время в отдельное поле created_at.

## Последствия
+ Сохраняется реальный порядок событий и время встречи.
+ Появляется основа для разрешения конфликтов правок.
- Часам устройства нельзя полностью доверять, потому что пользователь мог сменить время на устройстве. Аномалии видно по разнице между created_at и markedAt.

## Рассмотренные варианты
1. Только серверное время — теряется реальное время отметки, все офлайн-отметки получают время синхронизации.
2. Серверное время как основное, клиентское как дополнительное — тогда непонятно, по какому из них разрешать конфликты.
