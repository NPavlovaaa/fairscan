# 0002. Менеджер пакетов

Статус: принято · 2026-09-18

## Контекст
В репозитории несколько пакетов, и описание контракта нужно сразу двум из них.
Поэтому нужен менеджер с поддержкой workspaces. Все популярные это умеют,
поэтому выбор идёт по другому критерию — насколько строго менеджер изолирует
зависимости.

## Решение
pnpm, версия фиксируется через packageManager в корневом package.json.

## Последствия
+ Пакету доступно только то, что объявлено в его package.json, поэтому
  случайный импорт чужой зависимости падает сразу, а не через полгода при
  обновлении соседнего пакета.
+ Экономия места на диске: все версии пакетов лежат в общем хранилище,
  а в node_modules попадают ссылки на них.
  − Нужен отдельно установленный pnpm (или Corepack), иначе на новой машине
  проект не заведётся.
  − Редкие пакеты, рассчитанные на плоский node_modules, требуют
  дополнительной настройки.

## Рассмотренные варианты
1. npm workspaces — есть из коробки, но зависимости раскладываются плоско,
   поэтому пакету видно чужое.
2. yarn — решает ту же задачу изоляции, но через PnP, что требует
   совместимости инструментов; pnpm даёт сопоставимую строгость, оставаясь
   на привычном node_modules.
