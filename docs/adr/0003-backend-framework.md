# 0003. Фреймворк бэкенда

Статус: принято · 2026-09-18

## Контекст
Бэкенд решает узкий набор задач: несколько эндпоинтов (принять пачку отметок,
отдать список посетителей и отметки рекрутера), валидация данных, пришедших
с недоверенного устройства, проверка на дубли по id, хранение в SQLite.

Критерии выбора: типизация и явность. Проект на TypeScript, поэтому важно,
чтобы типы были частью фреймворка, а не надстройкой над ним. Поддерживает
бэкенд один человек, поэтому предпочтителен явный код без скрытой магии.

## Решение
Fastify. Схемы валидации берутся из packages/shared (Zod), типизация
маршрутов — через type provider.

## Последствия
+ Схема в маршруте даёт валидацию, типы и при желании OpenAPI-спецификацию.
+ Концепции близки к знакомому Express.
- Заточен под Node: на edge-платформу без переписывания не уедет.
- Для связки с Zod нужен дополнительный пакет.
- Экосистема меньше, чем у Express.

## Рассмотренные варианты
1. Express — самый распространённый, но типы прикручиваются отдельным пакетом,
   а валидации из коробки нет.
2. Hono — по типизации не хуже, TypeScript-first. Выбран Fastify как более
   близкий к знакомому стеку; переносимость
   на edge-платформы в этом проекте не нужна.
3. NestJS — навязывает модули, декораторы и внедрение зависимостей. Это
   окупается в больших командах, а для нескольких эндпоинтов даёт больше
   структуры, чем пользы.
4. Голый node:http — писать маршрутизацию и разбор тела запроса руками не
   входит в цели проекта.
